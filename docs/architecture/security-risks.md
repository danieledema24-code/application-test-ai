# Security risks

Threats mapped to spec §19, with mitigation and the phase that delivers it. "Ported" means the old `api/` already had the control and it moves to Python with its tests.

## Threat register

| # | Threat (spec §19 item) | Impact | Mitigation | Phase |
|---|---|---|---|---|
| T1 | **SSRF via submitted URL** (SSRF protection; private IP and metadata blocking) | Platform scans internal services or cloud metadata, leaking credentials | `security/ssrf.py` (ported): http/https only; no credentials in URL (`user:pass@` rejected); DNS-resolve all A/AAAA; block loopback, RFC1918, CGNAT 100.64/10, link-local incl. whole 169.254/16, multicast/reserved, `::1`, `fc00::/7`, `fe80::/10`, IPv4-mapped/compatible/NAT64/6to4 embeddings, metadata hostnames; non-standard ports allowed only for public hosts. `ALLOW_PRIVATE_TARGETS` exists for dev/tests only, is refused when `ENV=production`, applies only to the approved target origin, and permits **loopback only** (127.0.0.0/8, ::1, and hosts whose every address is loopback): RFC 1918, CGNAT and link-local stay blocked even in dev (QA found the URL check reaching a LAN router before this was narrowed); metadata is always blocked. | 1 |
| T2 | **SSRF via redirects** (redirect validation) | Public URL 302s to an internal address | URL check walks redirects manually (max 5), validating each hop. Browser: navigation requests fetched with `route.fetch(max_redirects=0)` and each `Location` validated; final URL re-validated after every `goto`. Cross-site redirects at intake are shown to the user and the new host is not auto-added to `allowed_hosts`. Phase 1 finding: Playwright does not route redirect-followed requests (navigations or subresources), so *every* routed request is fetched by the policy with `max_redirects=0` and each hop validated; redirected navigations are aborted and re-issued by the crawler after validation. `ALLOW_PRIVATE_TARGETS` (dev/test) is scoped to the approved target origin only. | 1 |
| T3 | **SSRF from page subresources / JS** (browser requests to internal IPs, DNS rebinding) | Target page makes the scanner browser hit internal services | Context-wide `route("**/*")` policy: resolve every new host (per-scan cache) and block private/metadata results; block non-http(s) schemes, WebSocket to private hosts, service workers. **Residual risk**: DNS rebinding between our resolution and Chromium's. Closed in Phase 5 by forcing browser traffic through an in-worker egress proxy that resolves once and connects to the validated IP (`--proxy-server` + `host-resolver-rules`), and in production by running workers in a network namespace/container with egress firewall denying private ranges. | 1 (policy), 5 (proxy + egress firewall) |
| T4 | **Browser escape / malicious content** (browser sandboxing) | Exploit in Chromium compromises the host | Chromium sandbox stays enabled (never `--no-sandbox` on macOS/local); fresh incognito context per scan, no persistent profile; downloads disabled; permissions denied; `bypass_csp=False`; no extensions; browser version kept current via pinned Playwright upgrades. Production: worker in separate container, non-root, seccomp profile, read-only FS except tmp. | 1 (local), 5 (container) |
| T5 | **Resource exhaustion** (per-project resource limits; execution timeouts) | Crawler traps, huge pages, endless scans starve the host | Max pages/depth (capped by org limits; default 30, cap 100), per-page 20 s and total 20 min timeouts (lead decision; was 10 min), DOM extract ≤2 MB, screenshot count bounded, URL normalisation + query-param explosion guard (same path with >20 query variants collapsed), max 2 concurrent scans per org, worker concurrency setting, job heartbeat + reaper. Phase 4: subprocess rlimits (CPU, memory, file size) and wall clock for test runs. Phase 5: k6 hard ceilings. | 1, 4, 5 |
| T6 | **Abuse of the platform as a scanner/DDoS tool** (rate limits) | Platform used to hammer third-party sites | Authorisation attestation at G1 (recorded, audited); politeness delay; single in-flight page per scan; rate limits (api-contracts.md); robots.txt respected by default; load tests only with approvals and caps (Phase 5). | 1, 5 |
| T7 | **Brute force / credential stuffing on login** (rate limits) | Account takeover | argon2id hashing; per (ip,email) failure throttle (ported); generic error text; enumeration-safe registration/forgot flows; session tokens are random and stored hashed; revocation on password reset (ported). | 1 |
| T8 | **Secret leakage** (secret management) | Test credentials, API keys exposed in DB, logs, prompts, reports | `.env` only for platform secrets (`SECRET_KEY`, `ENCRYPTION_KEY`, `ANTHROPIC_API_KEY`), `.env.example` without values; test credentials stored AES-256-GCM with key id (ported crypto), write-only API; redaction filter on logs, prompts, evidence text (ported `redact`); password inputs masked in screenshots and their values removed from DOM snapshots, ARIA snapshots (Playwright's ARIA snapshot includes textbox values; found and fixed in Phase 1 testing) and extracted page data; signed URLs instead of tokens in query strings. Generated TS reads secrets from env only (Phase 4 secret scan in validation). | 1 (platform + redaction), 2 (project secrets), 4 (script scan) |
| T9 | **Missing accountability** (audit logging) | Cannot prove who authorised a scan/run | Append-only `audit_logs` for auth events, project create/archive, G1 attestation, every gate decision, approvals, policy changes, secret create/delete, report download. PG: UPDATE/DELETE revoked for app role. Admin viewer + export in Phase 5. | 1 (write), 5 (viewer, PG revoke) |
| T10 | **Cross-tenant data access** (tenant isolation) | One org reads another's projects/evidence | `organisation_id` on every tenant row; `TenantRepository` filters; ORM safety net raising on unscoped queries; 404 on cross-tenant; storage keys prefixed by org and served only via API after tenant check / org-bound signed URL; worker rebuilds scope from job row. Cross-tenant test suite over every endpoint. PG RLS later. | 1, 5 (RLS) |
| T11 | **Prompt injection from website content** (prompt injection protection; untrusted content isolation) | Page text steers the LLM to fabricate requirements, exfiltrate context, or trigger actions | Architecture §7: content only in delimited untrusted blocks; LLM calls that see content have no side-effecting tools; navigation allow-list computed in code; strict schema + evidence-ref validation; provenance downgrade if unsupported; injection-pattern detector reports findings; secrets never in prompts; gates require humans. | 1 (discovery), every later phase per agent |
| T12 | **Prompt injection via uploaded documents / assistant chat** | Same as T11 through other inputs | Documents treated as untrusted evidence (same wrapping); assistant tools mapped to service functions with the user's permissions, no gate approval tool, destructive tools require confirmation UI. | 2, 3 |
| T13 | **Generated test code executing on the host** | Malicious/hallucinated TS reads files, spawns processes | Ported `spec-guard` (acorn allow-list) + tsc + eslint before save/run; runner subprocess with restricted env (only allow-listed vars), temp cwd, rlimits, network policy fixture; container sandbox when Docker exists. | 4 |
| T14 | **Destructive or transactional actions against the target** (explicit approval list) | Scanner deletes data, places orders, sends emails | Phase 1 discovery never submits forms or clicks; `SKIP_LINK` (ported) avoids logout/delete/unsubscribe/download links; later phases classify actions (destructive, external transaction, security test, load test, real user data) and require an `approvals` record per scope; G7 locked. | 1, 4 |
| T15 | **Real personal data in test data/evidence** (safe test data management) | PII captured or used in tests | Synthetic deterministic data factories; PII detector (email/phone/card patterns) flags evidence; "tests involving real user data" requires approval; retention settings per org (Phase 5). | 3, 4, 5 |
| T16 | **Hallucinated QA claims** (spec §2.5–2.7, reliability) | Users trust fabricated requirements or results | Provenance + evidence enforcement; results only from runner output; report numbers computed in code; AI-off fallback labelled; `rules`/`ai` labels in UI and reports. | 1 onwards |
| T17 | **XSS via captured content in the UI** | Page titles/text from the target run script in our dashboard | React escaping, no `dangerouslySetInnerHTML` for captured data; evidence served with `CSP: sandbox`, `nosniff`, and `attachment` for non-images; HTML reports rendered with autoescape and a strict CSP. | 1 |
| T18 | **CSRF / token theft** | Actions on behalf of a logged-in user | Bearer token in header (not cookie) → no ambient credentials; strict CORS (`WEB_ORIGIN` only); tokens never in URLs (signed per-file URLs instead). Risk accepted: token in `localStorage` is readable by XSS (T17 controls); move to httpOnly cookie + CSRF token when deployed on one domain. | 1 |
| T19 | **Supply chain** | Compromised dependency | Lockfiles (`uv.lock`, `package-lock.json`), minimal new deps, `pip-audit`/`npm audit` in CI. | 1 (lockfiles), 5 (CI audit) |
| T20 | **Job/worker interruption leaves inconsistent state** (reliability) | Stuck "running" stages, duplicate work | Durable jobs with heartbeat + reaper, idempotent handlers keyed by `dedupe_key`, stage transitions in transactions, resumable discovery frontier. | 1 |

## Explicit non-goals (stated in UI and reports)

- A public website scan is **not a security audit** (spec §10). Phase 5 security assessment is passive and OWASP-aligned (headers, cookies flags, TLS, mixed content, exposed files list from discovery) unless an approved, scoped active test is configured.
- No destructive exploitation, credential attacks or vulnerability scanning of third-party hosts.

## Verification

Each mitigation above has a test in the phase that delivers it. Phase 1 security tests: SSRF vectors (port of `api/test/security.test.ts`), redirect-to-private via local fixture server, subresource-to-private blocked in browser, metadata IP literal forms, cross-tenant 404 suite, login throttle, session revocation, signed URL expiry/tamper/cross-org, redaction of logs, prompt wrapper escaping (content containing `</untrusted_website_content>` is neutralised), injection detector flags fixture page.
