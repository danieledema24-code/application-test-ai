# API contracts

Base URL: `http://localhost:8200/api/v1`. JSON only (UTF-8). OpenAPI generated by FastAPI at `/api/v1/openapi.json` and is the machine-readable contract; this document is the design intent.

## Conventions

- **Auth**: `Authorization: Bearer <session token>`. Token = 32 random bytes, base64url; server stores only its SHA-256 (`sessions.token_hash`). Lifetime 12 h, sliding refresh on use after 1 h, revocable. Every endpoint requires auth except `health`, `auth/register`, `auth/login`, `auth/forgot-password`, `auth/reset-password`, and signed evidence/report content URLs.
- **Tenant**: the session's active organisation. Resources in other organisations return `404`.
- **Roles**: `viewer` read-only; `member` create/run/edit; gate approvals need `can_approve` (owners/admins have it by default).
- **Errors** (all non-2xx):
  ```json
  { "error": { "code": "validation_error", "message": "Human-readable summary", "details": [{"field": "url", "message": "..."}], "request_id": "01J..." } }
  ```
  Codes: `validation_error` 422, `bad_request` 400, `unauthenticated` 401, `forbidden` 403, `not_found` 404, `conflict` 409 (version mismatch, stage already running), `gate_blocked` 409, `DUPLICATE_PROJECT` 409 (see `POST /projects`; the one upper-case code, agreed with the web client), `url_blocked` 422 (SSRF policy), `url_unreachable` 422, `rate_limited` 429 (+`Retry-After`), `internal` 500 (no internals leaked).
  `details` is a list of `{field, message}` objects, except for `DUPLICATE_PROJECT`, where it is an object (below). Every response carries an `X-Request-ID` header equal to `error.request_id`.
- **Pagination**: `?limit=20&cursor=<opaque>` → `{ "items": [...], "next_cursor": "..." | null }`. Max limit 100.
- **Concurrency**: mutable resources return `version`; `PATCH` bodies include `version`; mismatch → 409.
- **Timestamps**: ISO 8601 UTC. **IDs**: UUID strings; human keys (`SCAN-0001`) in `key`.
- **Provenance fields** on every AI-derived item: `provenance`, `confidence`, `evidence_refs`, `generated_by` (`ai` | `rules` | `human`). The UI must label `rules` output ("Generated by rules, AI not configured").

Shared schemas (Pydantic style):

Always `200` with a result (blocked/unreachable are data, not errors). Uses `httpx` with `follow_redirects=False`, manual hop validation (max 5), 10 s timeout, 1 MB body cap, `GET` only. The DNS lookup of each hop is bounded by the same timeout (`unreachable_code: "dns_timeout"`).

`POST /projects` — the "Start QA Analysis" action
```python
class ProjectCreate(BaseModel):
    url: str
    name: str | None = Field(None, max_length=120)      # default: host name / page title
    description: str = ""
    authorisation: AuthorisationAttestation
    scan: ScanSettings = ScanSettings()
    start: bool = True                                    # immediately enqueue intake -> discovery
    confirmDuplicate: bool = False                        # camelCase on purpose (web client); `confirm_duplicate` also accepted
    credentials: {"login_url": str, "username": str, "password": str} | None = None
        # all three or none (else 422 per field); login_url must be on the site's host. Stored AES-GCM encrypted,
        # never returned. Phase 1 discovery does not sign in; the credentials are kept for later phases.

class AuthorisationAttestation(BaseModel):
    attested: Literal[True]                               # must be true
    statement: str = Field(min_length=10, max_length=500) # e.g. "I own example.com" (UI pre-fills)

class ScanSettings(BaseModel):
    max_pages: int = Field(30, ge=1, le=100)              # also capped by organisation.limits (default 30 per design)
    max_depth: int = Field(3, ge=0, le=5)
    include_mobile: bool = True
    respect_robots: bool = True
```
→ `201 ProjectDetail`. Server re-runs the URL check; if not `allowed` → 422 `url_blocked`; if unreachable → 422 `url_unreachable` (the project is not created). Records G1 decision (`approve`, by the user, with automated check result), audit `project.created` + `gate.approved`. If the organisation is at its concurrent-scan limit the project is still created and the discovery stage stays `queued` (the worker enforces the limit; an `agent_event` explains the wait). Errors: 429 on the project-creation rate limit; 409 `DUPLICATE_PROJECT` if a non-archived project in the organisation has the same normalised (or final) URL and `confirmDuplicate` is not `true`. Its `details` is an object: `{"project_id": UUID, "project_name": str, "primary_url": str, "field": "url"}`. Resending with `confirmDuplicate: true` creates a second project.

### Live progress channel (SSE)

`GET /projects/{id}/events/stream` — `Content-Type: text/event-stream`. Auth via `Authorization` header (client uses `fetch` streaming, not `EventSource`). Resume with `Last-Event-ID` header or `?after=<id>`. Server tails `agent_events` (poll 500 ms, or wake-up signal) and sends a `: keep-alive` comment every 15 s. Connection closes after 30 min; client reconnects with the last id.

```
id: 1842
event: agent_event
data: {"id":1842,"project_id":"…","stage_key":"discovery","agent_key":"discovery","task_id":"…",
       "type":"page.discovered","level":"info","message":"Found page \"Pricing\" (/pricing)",
       "data":{"page_id":"…","url":"https://example.com/pricing","screenshot":{"id":"…","content_url":"…"}},
       "created_at":"2026-11-12T10:15:03Z"}
```

Event types (Phase 1): `stage.status_changed {stage_key, from, to, version}`, `task.started`, `task.progress {done, total, label}`, `task.completed`, `task.failed {reason}`, `page.discovered`, `page.failed {url, reason}`, `evidence.captured`, `request.blocked {url, reason}`, `gate.awaiting_approval {gate, recommendation}`, `gate.decided`, `report.ready`, `log` (agent narration, user-readable). Event `data` never contains secrets or raw page text.

Non-streaming fallback: `GET /projects/{id}/events?after=<id>&limit=100` → `{items: [AgentEvent], next_after: int}` (also `?before=<id>` for paging backwards). Org-wide activity: `GET /activity?limit=&cursor=&milestones=true|false`.

Phase 1 notes on event `data`: every event has `kind` (`status`, `action`, `finding`, `warning`, `error`, `gate`); findings carry `label` (`observed`/`inferred`), `path` and `evidence_ids`. `page.discovered` carries `screenshot: {"id", "content_url"}`; the URL is re-signed whenever events are read (list or stream), so replayed events never hold an expired link. `task.progress` carries `done, total, label, screenshots, queued`.

### Phase 1 additions (implemented, additive)

These fields were added by the Phase 1 backend. All are optional for clients and none change an existing field's meaning. The OpenAPI document at `/api/v1/openapi.json` is authoritative.

- `Health.worker.mode` may also be `"off"` (no worker in this process). `Health.allow_private_targets` (see Health).
- CORS: `WEB_ORIGIN` may send `Authorization`, `Content-Type`, `Accept`, `Cache-Control`, `Last-Event-ID`, `X-Request-ID` (the SSE fetch sends `Cache-Control` and `Last-Event-ID`); `X-Request-ID` and `Retry-After` are exposed.
- `ScanDetail.partial: bool | None`: true for cancelled, time-limited, failed or page-limited scans (unvisited frontier); false when the whole site was seen; null while running. Same rule as the report's `content.partial` / `ReportSummary.partial`.
- `ScanDetail.stop_reason`: `page_limit | exhausted | cancelled | timeout | paused | failed` (null while running). The G2 recommendation's advice follows it (re-run after cancel/time limit/error, higher page limit only after the page limit, credentials when areas need sign-in). Limitations, completeness, access gaps and the sitemap's not-visited reason follow it; "page limit" is only reported when the limit was actually reached.
- Auth boundaries vs access gaps: a sign-in page that loaded is reported in `auth_boundaries` (`kind: login_form`) and its page has `requires_auth: false`; it is not an access gap. Access gaps with reason `Needs credentials` are the URLs that answered 401/403 or redirected to sign-in; when the only sign-in signal is a visible form, there is exactly one such gap, `area: "Signed-in area behind /login"`, suggesting test credentials. The same areas drive the G2 line "N area(s) need credentials", the summary and the "Some pages need a sign-in…" limitation.
- `ProjectSummary`: `access_gaps: int`, `scans: int`, `current_activity: str | None` (latest narration while running).
- `ScanSummary`: `number`, `stage_run_version`, `created_at`, `is_latest`. `ScanDetail` adds `summary`, `summary_generated_by`, `skipped_links: list[{url, reason}]` (reasons: `would end the session`, `destructive action`, `file download`, `robots.txt`, …), `external_links`, `not_visited: list[str]` (URLs left in the frontier), `injection_flags`, `robots`, `queue_position`, `gate`, `project_id`. `stats` adds `pages_failed, dropdowns, tabs, pagination, components, screenshots, queued, access_gaps, elapsed_s`. `completeness` adds `checks: list[{status: ok|warn|fail, text}]`. `current` adds `screenshot`.
- `AccessGap` adds `area`, `reason` (fixed vocabulary: `Needs credentials`, `Not performed: destructive or transactional action`, `Not visited: page limit`, `Not visited: discovery cancelled`, `Not visited: time limit`, `Not visited: discovery stopped early`, `Not visited: robots.txt`, `Blocked by bot protection`, `Outside scope (blocked address)`, `Couldn't load (…)`), `evidence_refs`. `AuthBoundary` adds `login_url`.
- `PageSummary` adds `path`, `status: visited|failed|blocked`, `failure_reason`; `PageDetail` adds `links`, `scan_id`. Form field `constraints` adds `minlength`.
- Journey steps add `label: observed|inferred` (a step that was navigated is observed; filling or submitting a form is inferred, never performed).
- `DiscoveryReportContent` adds `site, organisation, project, scan, gate1, approval, counts, key_observations, partial, partial_notice, mobile_included, generated_at, glossary, recommendation`.
